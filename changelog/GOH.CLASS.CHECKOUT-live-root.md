* **A gate run from a checkout resolves its goh from that checkout, whatever GOH_LIVE_ROOT an ancestor exported (`GOH.CLASS.CHECKOUT`).** The v0.119.0 ship failed at its release step: goh ship runs the release from the main checkout's HEAD export, which exports `GOH_LIVE_ROOT`, and the release kit's new loaded-suite step ran the suite in the release worktree with it inherited, so every gate a test ran there resolved its binary from the main checkout's store (0.118.0 serving a tree declaring 0.119.0, "BEHIND the source", 80 tests red). `gates/_goh_bin.sh` now honours `GOH_LIVE_ROOT` only from an export (`.goh-head` at its root), the one place it is for, as `crate::gitutil::root_commit` already did. The worktree's place was not the cause: `tests/test_live_root_leak.py` runs a release worktree inside the checkout (`build/`) and outside it (the run root) under a leaked root, and both were red before the fix; an export still finds its binary in the live root.
