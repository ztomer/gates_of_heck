* GOH.HEADCOPYRECORD: the code of record that may migrate the shared goh.db and goh-cache.db is now decided by its commit, not by whether its directory has a `.git`. On 2026-11-24 a lane's pre-commit ran `lib/commit_stamp.py record` from an export of its staged tree in `~/.cache/goh/head/` (no `.git`), the rule read that as an install, and migration 0009 reached the real goh.db ("by goh unknown") before 0009 was on main. Now the primary checkout is of record on main, and an export is of record only when the commit it names is on main's tip in the checkout that made it; a lane's commit, a staged tree, or a copy that names no commit opens a shared file read-only when it lacks a migration. The answer is kept per process: about 8 microseconds per open after the first, which costs 0.02 ms for the checkout, 0.2 ms for an export of main's tip and about 10 ms for an export of an older commit. An export's writer is recorded as `goh export <sha>` in place of `goh unknown`.
* A store write that this copy may not make (a newer goh's file, or a shared file only main's code migrates) now prints one line and the step continues. Before, it raised. The release canary raised that error after its verdict while 0009 sat in the real goh.db, so every land went red. This covers the estate state, commit stamps, flakes, the land ledgers and ship rows.
