* GOH.BATCHGITFAIL: a git read that fails or times out no longer becomes an empty string in the landing queue's batch (`lib/landq_batch.py`). `git()` answered '' on any failure, so after one failed rev-parse every later one looked like a tree already gated red (a stack reported `gated red` without being gated), and a landed stack with an unreadable main recorded `sha=''` on each done record. Every batch read is now strict (`GitFailed`): the step stops loudly with the git error in the lander log and each stopped item's own log, the stacked worktrees go back to their enqueued commits, and the requests not yet judged go back to pending for the lander's next pass (recorded red with the git error after 3 passes, 30 s apart). A stack the gate had already landed is read again three times; if main stays unreadable its items (and a single land's) are recorded red with their enqueued sha and the reason, never an empty one. Pinned by `tests/test_landq_batch_git.py`.
