* **`goh shell-check` and `goh zsh-split-guard` judge the shell the harness really runs, not the `CLAUDE_CODE_SHELL` setting (GOH.SHELLCHECKREAL).** The Claude desktop app runs `/bin/zsh` for a session and its subagents whatever `~/.claude/settings.json` names, yet `shell-check` printed "agent tool shell: bash 5.x" because it probed the setting: an instrument that could not say wrong, while lanes read an empty `${PIPESTATUS[0]}`. Both now read the shell from what the harness did (`crates/goh/src/toolshell/observed.rs`): a tool-shell ancestor (`<shell> -c source <config>/shell-snapshots/snapshot-<shell>-*.sh`, counted only for this config's snapshot directory, so a test with its own `HOME` stays hermetic inside a tool call), else the newest `snapshot-<shell>-*.sh` under `CLAUDE_CONFIG_DIR` or `~/.claude`, else the setting. `shell-check` exits 1 when the seen shell is not bash though the setting names bash, saying where it was seen and the remedy (run agents from the claude CLI; write commands zsh-safe meanwhile), and its green line names its witness. The guard also refuses `$PIPESTATUS`/`${PIPESTATUS[..]}` under zsh, naming `${pipestatus[1]}` and capturing the rc before the pipe; `# zsh-split-ok: <reason>` still escapes. `toolshell/observed_tests.rs`.
