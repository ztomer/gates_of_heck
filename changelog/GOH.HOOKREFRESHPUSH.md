* `goh hooks --refresh` pushes what it commits (GOH.HOOKREFRESHPUSH). It committed "chore: refresh goh's stock hooks" in each consumer and pushed none, so on 2026-11-15 six consumers sat ahead of origin with nothing but hook commits until a hand sweep. The refresh now pushes through the same door the pin sweep uses (`consumer_pins.push`, the consumer's own push gate): a hook-refresh commit touching only `.githooks` is goh's own like a pin commit, so a refresh pushes any an earlier one stranded, a pin sweep carries them too, an owner's commit ahead leaves the repo committed and named, and a refused push is that repo's failure with its gate's lines.
