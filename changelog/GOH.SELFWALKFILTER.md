* **`goh structural --only STEP` runs only the named steps, and the self-walk is split into parts xdist spreads (GOH.SELFWALKFILTER).** The pipeline is now ONE table (`crates/goh/src/structural/pipeline.rs`): every step, in order, under the name `structural_steps.txt` carries, so `--only` (repeated, one step per flag: `no temp, lock or stage path in a work tree` holds a comma) skips a step before it does any work, a delegated checker included, and a name the binary does not carry is refused (exit 2) by name rather than a run of nothing that prints the pass line. Every carried step is dispatched exactly once (`pipeline::tests::every_carried_step_is_dispatched_once`, red when one name is dropped). `tests/test_self_walk.py` was one case paying a cold shell lint and a serial `structural --full --keep-going` over two trees (56-70 s; allowed 150 s in `tests/long_pole_allow.json`); it is now seven cases, one per part of the registry (the five dearest steps apart, the shell-source steps, the rest, the `goh <cmd>` scanners), each walking both trees with `--only`. Only the shell part lints, and its verdict store is kept across sessions in goh's state (`self-walk-verdicts`, each record dropped after 30 days; a verdict is keyed by the file's bytes, its sources, shellcheck and the flags), so a session lints only the shell files whose bytes are new to it: a store per session paid a cold lint of every shell file once a session, 20 s quiet and 91-113 s in a loaded pre-step, in that one case. The planted tree's edited file and shell plant carry a per-session nonce, so the planted walk lints exactly those two every session and GOH.SELFWALKSC's pin is sharper: the walks lint nothing in the clean tree. Its long-pole allowance and its 60 s setup ceiling (`tests/_drift_guard.py`) are deleted.
