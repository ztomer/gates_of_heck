* **The ship takes a binary test's stored profile by its exact key instead of running it** (GOH.COVPROFILEREUSE). v0.140.1's ship spent 881 s of its 918.9 s suite step in the instrumented pytest and read 0 stored profiles, though 9 of the 10 ships before it changed no Rust input: its @tree plan took none, the store keyed profiles by tree, and the instrumented goh's bytes moved with every release (`lib/goh_version.sh --coverage` named the release HEAD sits past; it now names the one the last build-input change sits past, so four ships whose Rust inputs last changed at e7bf6d43 build one binary, not four). Each binary-running test's profile is now kept under the binary's content hash, the node, the content of what its test file reads (the file, the affected-tests graph's reach, the base, its declared reads; tree readers and undeclared readers always run), the tools with llvm-profdata, and the GOH_COV_* settings; a ship whose key matches deselects the test and links its profile into the report, so the floor is judged on the merged result. One ship in ten is the new `profreuse` audit's shadow: the matched tests run, and a repeated difference between the counters their stored and fresh profiles cover turns the path off and files a fault. The ship record's `suite` step names reused and fresh per binary (`profiles`). Hosted release CI still measures afresh.
