* GOH.VERDICTDB: the reuse verdict records (`gate`, `pushed`, `carry`, `affected`, `relset`, `profcarry`, ...) are rows of goh-cache.db's `verdicts` table (cache migration 0002, which also creates the `kept` and `memo` tables the kept stores and the identity memo move into), written and read through `lib/reuse_store.py`; `lib/reuse.py`'s `record`/`lookup`/`records`/`prune` API is unchanged except that a record's locator is `<db>#<path>/<key>`, not a file path. The cache is disposable: a database error or a deleted file is a miss, never a raise. Record files from before the switch are read when no row exists, copied in and pruned at their TTL, so a year of `pushed` floor bases survives the land. `prune` also caps each path at its newest 20,000 rows. A land suite's controller records into the caller's goh-cache.db, named by the runner (`GOH_LAND_VERDICTS_CACHE`), the one real-home cache file a suite may write.
* GOH.VERDICTDB: `lib/bin_reach.py`'s measured-free tests read the newest carry records through `reuse.records`, not by globbing the record files, which the move left empty (every measured-free test would have been chosen again).
* GOH.VERDICTDB: `lib/identity_cache.py`'s memo (the `git ls-files` listing and the build inputs) is goh-cache.db's `memo` table, 512 rows per kind, not 512 files under `~/.cache/goh/identity`; `GOH_IDENTITY_CACHE` now names a directory whose `goh-cache.db` holds it. A table the shared file has not got yet is a silent miss, and a write a lane's copy is refused is said once per process, not once per write.
* GOH.VERDICTDB: the suite's parse findings (`tests/_parse_findings.py`) are goh-cache.db `kept` rows, not files in the real goh state written by every xdist worker: a worker writes only the suite's own goh-cache.db (one transaction per batch), and the controller seeds it from the real file at the session's start and merges the session's new rows back once at its end (INSERT OR IGNORE; rows past 30 days dropped). The real file is named by the runner (`tests/suite_home.py`) and taken out of the environment when the plugin loads, so a pytest session a test starts never writes it. `goh state` registers the kept stores with their bounds and no longer names `parse-findings` or `tree-lint-verdicts` as "entries and no bound" (GOH.VERDICTBOUND); the two shell-lint stores stay files the goh binary reads until V2.
* GOH.VERDICTDB: the reuse audit's records are goh.db rows (migration 0008: `reuse_audit`, one per path, and `reuse_shadow`, one per compared sample), behind `lib/reuse_audit_store.py`; it is durable state, not cache, because a lost OFF record would turn a wrong reuse back on. `lib/reuse_audit.py`, `lib/reuse_fault.py` (and so the SessionStart advisory) read and write only the store; record files from before the switch are read when no row holds the path, and `reuse_audit_store.py import`/`export` round-trip the files (the `imports` ledger). A land suite's controller counts into the caller's goh.db, named by the runner (`GOH_LAND_VERDICTS_AUDIT_DB`).
* GOH.VERDICTDB: `reuse/profreach` (the binary reach's index of the profile store, one ~0.8 MB file per key) and `reuse/binreach` (the reach audit's 200-row ledger) stay files by decision: neither is many small files nor written concurrently, and profreach's validity and prune read the profile store's own directory. Both are registered in `lib/state_bounds.py` with the reason, and `tests/test_reuse_root_files.py` refuses any directory kept under the reuse root without a registration.
