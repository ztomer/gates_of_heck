* **The long-pole ratchet judges each test's quiet seconds, not the wall of its last loaded run (GOH.LONGPOLELOAD).** It went red on two lands whose diff touched neither test: `tests/test_self_walk.py`'s shell case read 168.2 s against its 150 s allowance at load ~50, and the ratchet's own real-tree test went red the same way. Every phase's report now carries `goh_pole` (`tests/_drift_guard.py`), and the top-level run sums those into a long-pole table beside the duration table (`lib/fast_tests.py` `poles`, `tests/_schedule.py`). `goh_pole` comes from the phase's wall, the CPU of the process and the children it waited for, and a stretch measured on the test's own thread when the phase ends: the wall of the speed probe's fixed loop over what that loop costs a quiet core. `lib/long_pole.py` `pole` takes the larger of wall minus CPU times (stretch - 1) and wall over stretch. That is never above the quiet time, so load alone cannot turn a test red. A test that grew by waiting keeps its whole wall, and one that grew by CPU keeps its CPU, so a test that really grew is still red. The load average was rejected as the stretch: at load 29 on 16 cores it read x1.8 where a test burning one core lost nothing. An allowance is now stale when the standing set stops running its file, not when the young table has not measured it yet (`tests/test_long_pole.py`).
