* **A nested lock is its holder's, and another repository's lock is not ordered against yours (`GOH.LOCKNEST`, after GOH.LOCKORDER).** A 0-spinner `tools/load.py` run under an ancestor that holds the load slot now runs in that ancestor's slot: it took a second place of its own (inside an experiment holding the slot alone it waited `--wait-max` on its own parent, exit 3). The gate slot `structural.sh --full` takes for a consumer's `tools/gate.sh` is now seen by the lock order from that gate.sh's later layers, which no exported variable reaches (the slot's record names the owner; a wait ranked below the slot asks it). And `lib/lock_order.tsv` gains a scope column: a `repo` lock (lander, ship, land, tree) of one repository is ordered only against locks held in that repository (`GOH_HELD_LOCKS` entries carry `:key`, a hash of the git common dir) or in none, so a consumer's test that runs a fixture repo's ship or land under its own gate is no longer refused (`.loop`'s `test_ship_done`, scrubbed by hand in .loop 0b7e419).
