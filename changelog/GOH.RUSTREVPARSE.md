* The goh binary no longer spawns `git rev-parse --absolute-git-dir`, `--path-format=absolute --git-common-dir`, `--path-format=absolute --git-path index` or `--is-shallow-repository`: `gitroot` reads the same layout it already read for the top level (a linked worktree's own git dir and the shared one, its `index`, the absence of a `shallow` file) and asks git for anything it does not model, under the same refusals (steering variables, bare, `core.worktree` or a `config.worktree`, includes, a crossed mount, another owner; `GIT_INDEX_FILE` and `GIT_SHALLOW_FILE` too). `extensions.worktreeConfig` alone no longer makes the layout uncertain, which it did in this repository's own shared config: every lane's worktree asked git before. Callers moved: `run_path`, `rust_depinfo`, `shapes/diff`, `index_view`, `credurls`, `gitutil::is_shallow`. Parity against git is tested on plain, symlinked, worktree, shallow (and its worktree), submodule, bare, inside-the-git-dir, `core.worktree` and `worktreeConfig` fixtures; `tests/test_goh_git_spawns.py` pins zero such spawns from the binary. A `structural --full` of this repository started 8 of them (GOH.RUSTREVPARSE).
