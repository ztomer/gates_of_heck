* **The agent tool shell is checked at session start, and zsh's no-word-split trap is refused while it lasts (GOH.ZSHSPLITGUARD).** Three commands ran wrong on 2026-11-21 because zsh passes an unquoted `$VAR` as one word: `git commit -- $F` with a list, `$L done X` that ran nothing 20 times, and a `for f in $FILES` that overwrote a lane's uncommitted edits. `goh shell-check` (a SessionStart hook) exits 1 naming each fix unless `CLAUDE_CODE_SHELL` is a bash >= 5 and a `bash -c` under `BASH_ENV`, in an empty environment, yields `GOH_DIR`, `PYTHONPATH` holding it and `AGENT_ENV_LOADED=1`. `goh zsh-split-guard` (a PreToolUse hook on Bash and Monitor) parses the command with `brush-parser` and, only while the tool shell is zsh, denies an unquoted `$VAR` used as a command word, a `for` list or an argument after the same command assigned it a whitespace-holding value, naming the array, function and inline fixes; `# zsh-split-ok: <reason>` escapes. `scripts/apply_claude_hooks.py` installs a `"$GOH_DIR/bin/goh" <subcommand>` hook as it installs a script. The test suite drops `BASH_ENV` and `ENV`: an inherited `BASH_ENV=~/.bashrc` rebuilt every bash child's PATH under the suite's throwaway home, and the suite would not start.
