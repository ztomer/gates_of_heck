* A goh release now lands every pin goh owns in a consumer, not just commits it (GOH.PINPROPAGATE). One manifest, `lib/consumer_pins.py` PINS, names them: the goh release a workflow checks out, and goh's ruff (`ruff==X.Y.Z` in the root pyproject.toml, a root requirements*.txt or a workflow's install; the uv.lock beside it relocked by `uv lock`, the repo's .venv given that ruff), each read from its one writer (goh's tag; `required_tools.tsv` via `ruff_house.RUFF`). `goh wf-pin --bump`, goh ship's install step, moves them in one commit per repo and pushes it through the repo's own push gate, together with any pin commit an earlier bump stranded; an owner's unpushed commit is never pushed (the pin waits on it, named), and a land holding the repo's lock sets it aside. Each repo's outcome is written beside the ship result and carried as `consumer_pins`, said by `--status` and the verify card. Before it, ruff moving 0.17.4 -> 0.17.5 left four consumers refusing every commit, and v0.121.0 left about 17 repos ahead of origin with an unpushed pin commit. A consumer's gates run by goh no longer inherit the ship's `GOH_SHIP_*` or `GOH_GATE_VERDICTS` (`estate_commit.env`).
