* goh's per-run temp roots reuse their names instead of taking a fresh random one per run (GOH.FSCHURN). fseventsd sat at one core and 11.7 GB, growing 55-90 MB/min, with goh 78-99% of the file events on /. An experiment on 2026-11-18 ran 50,000 mkdir+create+unlink+rmdir at 450/s in each arm, and fseventsd's RSS grew 278 MB in 97 s under unique directory names against 150 MB under one reused name. The reused-name growth sat inside the 0.55-2.07 MB/s of the quiet samples. Three things changed. Every gate's pytest root (`gates/_pytest_root.sh`) is now the lowest free `goh-pytest.slotNN`, claimed by an atomic mkdir. The suite's home (`tests/suite_home.py`) is the lowest `home.slotNN` whose flock is free, and a killed run's leftovers are emptied before the slot is reused. The test helpers' per-process dirs (git seed, template homes, cargo shim and build dir, coverage cache, push worktrees) are named `<prefix><xdist worker>.<n>` through `tests/_reused_tmp.py`. Past the last slot, or on a taken name, each falls back to a fresh name as before. `lib/temp_sweep.py` now also refuses a glob over the slot names. Measured with an FSEvents recorder over two back-to-back runs of `tests/test_push_gate_runs.py` and `tests/test_tree_clone.py`: before, 98% of the second run's distinct temp paths were paths the first run never touched (6176 of 6303); after, 47% (3292 of 7043). What remains is xdist worker placement (`popen-gwN`), git object names from commit timestamps, and names stamped with a pid or time. The total event count does not change.
