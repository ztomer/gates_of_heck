* **Every goh temp, lock and stage path comes from one helper rooted outside the work tree (`GOH.CLASS.CHECKOUT` part 2).** goh wrote its own scratch into the checkouts it serves: `bin/.build.lock` (scripts/build-goh.sh), `bin/goh.<pid>.staging` (lib/place.sh), the `build/release-vX` worktree (tools/release_goh.sh), `<repo>/.goh-tree.lock` (lib/tree_lock.sh), and `git write-tree` on the shared index (gates/_proven.sh, gates/_self_gate.sh, crates/goh/src/proven.rs), which takes `index.lock` and failed while another git held it. Now `lib/run_path.sh` (`goh_run_dir TREE`, `goh_index_tree`), `lib/run_path.py` and `crates/goh/src/run_path.rs` mint them under `GOH_RUN_DIR` (default `~/.local/state/goh/run/<basename>-<16 hex>`), one key in all three faces; the tree of the index is written from a private copy, so no gate takes the shared lock. The release worktree is one stable path, so its land gate's cargo build-dir is reused release to release. A placement stages beside its destination only when the run root is on another filesystem. The class is structural: `goh run-paths` (opt-in `GOH_RUN_PATHS`, on in goh; floor `GOH_RUN_PATHS_MIN_FILES`; seed `run_paths_seed.json`, landed empty; escape `run-path-ok: <reason>`) refuses a temp, lock or stage name rooted at a work tree, a path in a tree's `build/`, or a bare `git write-tree`. Over the tree it replaced it names exactly the seven sites and the hookindex scanner's table. `tests/test_entry_points_leave_no_strays.py` now runs the placement, the tree lock, the proven index tree (with another git holding `index.lock`, and inside a real `git commit -a`) and the release kit's worktree, each leaving no file in the work tree (red on the old code: five of them).
