* GOH.LONGPOLEUNMEASURED: a long-pole reading taken under load is unmeasured, never a verdict. The long-pole table (`fast_tests.poles()`) is shared by every land and held each test's LAST reading, corrected by one stretch sample as the test ended; at load 47-72 on 16 cores `test_self_hosted_hook` read 61.9 s (quiet 21.8-26 s, CPU unchanged) and `tests/test_long_pole.py` refused every land after that run. Now each phase also carries its CPU seconds and whether the run queue over it passed `QUIET_LOAD` (1.5 runnable per core, `tests/_drift_guard.py` `run_queue`); a test read under load keeps its entry as the last quiet run read it (`lib/long_pole.py` `settle`), unless its CPU grew `GROWTH` (1.6x) over that run's, which the load alone cannot do on Apple silicon (+37% at 10x load): then its quiet seconds grow by the CPU it added over the cores it spread over, so a real 2x growth is red at any load. The entries' CPU seconds live beside the table (`fast_tests.pole_cpu()`, `test-durations.poles-cpu.json`).
