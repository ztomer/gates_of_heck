* **Consumers stop holding copies that can go stale (`GOH.CLASS.ROLLOUT`, `GOH.REFRESHLEAVES`, `GOH.WFPIN`).** The class: estate rollout lag -- 33 repos ran stale stock hooks (2026-11-15), every workflow pinned an old goh tag, and `goh hooks --refresh` wrote a 17-line `goh_dir_repair` block into the tracked `tools/gate.sh` of 14 repos and committed none of it. Three closures. (1) Every stock hook is now ONE POSIX shim, the same bytes under every name, that finds the gates_of_heck checkout (GOH_DIR or GOH, GOH_LIVE_ROOT, the house default, the repo itself) and runs its `gates/hook.sh`, which holds everything a hook used to carry (bash 5 guard, the dead-GOH_DIR fallback, the dispatch, the git unbind): a goh change reaches every consumer with no refresh, and the shim's bytes are pinned as an ABI (`tests/test_hook_shim.py`; red with the old pre-commit: the changed hook.sh never ran). The previous stock hooks are retired; they delegate, so they are warned, not refused, until the one last refresh. (2) `install.sh` never edits an existing `tools/gate.sh` (the `goh_dir_repair` migration is gone; a hook-run gate inherits the GOH_DIR hook.sh repaired), and every write into another repo goes through `lib/estate_commit.py`: it snapshots the status and the bytes of each uncommitted file, puts back and names anything the writer touched outside the paths it owns, commits the rest through the repo's own hooks or restores it, and says "left as it was" only after reading the status again. `test_a_refresh_leaves_no_tracked_file_dirty` was red on today's refresh (` M tools/gate.sh`) and `test_a_refused_refresh_leaves_status_exactly_as_before` red too (another agent's uncommitted gate.sh rewritten under an unchanged status line); `test_estate_commit.py` went red with the stray check disabled. (3) `goh wf-pin` lists every estate workflow whose goh pin (`repository:`+`ref:`, `GOH_TAG:`, `git clone --branch`) is behind goh's newest tag, and names a goh checkout pinned to none; `--bump` commits the workflow files alone through the same door, never pushing, and goh's `.gatesrc` GOH_SHIP_INSTALL (`tools/ship_install_goh.sh`) runs it after every goh release.
