* GOH.GATEBUDGET2: `goh budget` sees what GOH.GATEBUDGET left unmeasured. Every landing-queue request is now one `<repo> land attempt` row in the timing ledger, red and timed-out ones included, and its done record names its `item` and `attempt` (a re-enqueue after a red is attempt n+1). `goh budget` judges each item's chain of attempts as one `<repo> land retries` run of their summed wall and prints it as `GOH.X: 2 attempts: red 537 s, landed 300 s = 837 s` (`lib/land_attempts.py`). `tools/pytest.sh` writes a `goh suite` row for each whole run (`goh suite:carried` when it reused verdicts) with the CPU seconds of its process tree, which load does not move the way it moves the wall. The CIP lanes' measured push gates are backfilled as `<repo> push` rows (`lib/cip_history.py`, from `cip_history.json` in the private seed store, `GOH_SEED_DIR`), so each repo a CIP lane brought under 10 min starts ARMED. A subject's runs are now judged in time order, so a backfilled row never reads as the newest run. Pinned by `tests/test_land_attempts.py`, `tests/test_suite_timing.py` and `tests/test_budget_backfill.py`.
