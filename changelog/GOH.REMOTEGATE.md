* The land gate's suite shares with the remote worker (GOH.REMOTEGATE; owner 2026-11-23: "the worker is mostly idle during landing, can't it help somewhat?"). The gate's whole run (`tests/_land_remote.py`, rules in `lib/remote_gate.py`) sends the `tests/linux_safe.txt` files it still has to run after the land's carry to the worker through `lib/remote_lane.py`'s own split (sized by the measured `Rates`, so a loaded worker takes less), launcher and junit reading; those files leave the Mac's run and the worker's verdict counts for the land: a test that fails there is red and named, a fallback runs the files on the Mac. The worker's passes are counted as another verdict's, so the verdict store's record is never `full` and `goh ship` still reruns everything on the Mac before a tag. One gate in ten (`GOH_REMOTE_SHADOW`) is a shadow: the Mac runs the share's files too, and a module whose verdict differs between the platforms joins the disagreement ledger (`linux-unsafe.json` beside the duration table), which takes it out of the list for every later split. `GOH_LAND_REMOTE=off` keeps the gate's suite on the Mac as it keeps the pre-step.
