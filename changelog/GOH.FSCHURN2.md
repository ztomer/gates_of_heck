* **The suite's file events are counted every whole run and held under a ceiling; templates are built once per run and packed** (GOH.FSCHURN2). GOH.FSCHURN made the temp roots reuse their names, which bounds fseventsd's path table but not its work: one record per file event, and two days later the suite was back at ~800 fresh directories a second with nothing measuring it. `lib/fs_events.py` reads an FSEvents stream (CoreServices through ctypes, no sudo) and names each event's creator from its path (the test whose tmp_path it is, a mkdtemp prefix, a reused per-worker dir); `tests/_fs_churn.py` runs it in the controller over the run's own roots (its TMPDIR and suite home), writes the count to `$GATES_OF_HECK_FS_EVENTS` (tools/pytest.sh names it for a whole run and records `fs_events`/`fs_dirs` in the `goh suite` ledger row) and turns the run red over `tests/fs_events_ceiling.json` (one test's own events, or the mean per test run). Measured: a clonefile(2) of a 1000-file tree is 3 events, its removal 1021, so a clone per test is cheap to make and full price to tear down. `tests/_tree_clone.py` `template` now builds each template once per RUN (the first worker, under an flock, published by one rename) instead of once per xdist worker, and every repository a template holds is repacked to one pack, so a test's clone carries no loose objects to remove. `tests/test_required_tools.py`'s PATH-without-a-tool mirrored every executable on PATH (~2960 symlinks) into each test; it now shadows only the PATH directories holding the tool, built once per run (17707 -> 3643 file events for the module, 3348 entries left to the run's removal). The ceiling's per-run mean counts what a run leaves under its roots (`left_behind`), so a cut that only moves removal from a test's teardown to the run's is not free.
