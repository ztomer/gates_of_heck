* GOH.QUEUESCHEMA: goh's Python reader of the loop's queue (`lib/queue_read.py`) returns `archive.items` rebuilt from the store's archived rows in seq order, as the loop's own load does; before, it returned the stored null placeholder, which the loop's triggers raised TypeError on, so `tests/test_filer_live_rules.py` (7 tests) was red and every land with it. `tests/test_queue_read.py` plants an archive by the documented layout and, where the loop is checked out, through the loop's own writer, and compares with the loop's own load. (The Rust reader reads statuses only and already counted archived rows.)
* GOH.QUEUESCHEMA: both goh readers of loop.db (`lib/queue_read.py`, `crates/goh/src/roadmap/queue.rs`) read it by layout, never by a list of schema numbers: the loop's versioned views `queue_v1_keys` and `queue_v1_items` (LOOP.QUEUENORMAL) whenever both exist, whatever the tables under them and the `user_version`; else today's `queue_keys` and `items` tables (a schema-1 file, and any later additive change to it). A store without what is read is "no queue" naming the missing table or column (`lacks items.body`), and a file with neither the views nor a `user_version` of at least 1 stays refused. Before, any `user_version` but 1 was "no queue", so the loop's next migration would have blinded every goh reader.
