* **A changelog entry is its own file, so two lanes never edit one (`GOH.CLASS.CHECKOUT` part d).** Every lane land of 2026-11-14 conflicted on CHANGELOG.md, four times in one night, because each lane wrote the same `## Unreleased` stanza. With `.gatesrc` GOH_CHANGELOG_FRAGMENTS=on (goh's own; opt-in, consumers unchanged) an entry is `changelog/<ITEM-ID>.md`, top-level `* ` items and no heading (`tools/release-kit/changelog_fragments.py`). `changelog_cut.py cut|ready --fragments DIR` folds them into Unreleased in name order before it cuts; `check --fragments DIR` refuses one left at the tagged commit; `fragments --fragments DIR` lists them for the release commit to delete. `tools/release_goh.sh`, the kit's step 0b (`release_fragments` in `version_step.sh`, and its changelog step's check) and goh ship's changelog reading (`lib/ship_changelog.py`) read the key. What makes the shared stanza unwritable, not discouraged: the structural step `no changelog entry under Unreleased` (`crates/goh/src/changelog_fragments.rs`) refuses a commit whose changelog holds a line under an Unreleased heading; a release cut leaves it empty, so the release commit passes the same rule with no guess at which commit is a release. `tests/test_changelog_fragments.py` (red with the fold removed: the cut found Unreleased empty; red with the step unwired: a commit with an Unreleased entry was accepted).
