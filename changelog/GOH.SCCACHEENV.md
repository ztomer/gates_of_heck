* **goh no longer puts cargo's own settings in rustc's environment, where sccache hashed them into every key (GOH.SCCACHEENV).** sccache 0.19 hashes every `CARGO_*` variable rustc inherits into the Rust key. The suite's cargo shim exported a per-run `CARGO_BUILD_BUILD_DIR` (and `CARGO_INCREMENTAL`), and `lib/step_control.py` exported `CARGO_TARGET_DIR` per copy, so every run's compiles got keys no other build shared: 68.0% of the machine's Rust misses over 8.5 h (design GOH.CACHEEVICT section 4, F1). Both now pass `--config build.build-dir=...`, `--config build.incremental=false` and `--target-dir` on cargo's command line. The shim puts them after the subcommand's name unless the caller has its own `--config` before it: probed on cargo 1.100, any `--config` after the name drops every one before it, and `clippy` drops one placed before its name. Measured on a private sccache server, a fixture with a path dependency built by two workers: the old shim's second worker got 0 hits of 2, the new one's 2 of 2. `tests/test_suite_drift.py` (a recording rustc wrapper, checked against the real cargo; red on the old shim with `CARGO_BUILD_BUILD_DIR`; also red when the config goes only before or only after the name), `tests/test_step_control.py` (red: no `--target-dir`).
* **The gate check_cargo_env_spread (`tests/test_cargo_env_spread.py`) refuses any goh code that sets a cargo config variable for a cargo it runs.** Its allowlist names each remaining set and why it spreads no key (coverage runs with `RUSTC_WRAPPER=""`, fakes, `cargo fetch`/`cargo update`, the suite's moved HOME), and an entry the tree no longer has fails. Calibrated red on the old tree: `lib/step_control.py:136` and `tests/test_goh_tui_version_line.py:91` (now `--config build.target-dir` after the subcommand).
* **`lib/goh_rustc.sh`, a rustc-wrapper to put ahead of sccache (F1b), drops `CARGO_TARGET_DIR`, `CARGO_HOME`, `CARGO_INCREMENTAL`, `CARGO_BUILD_*` and `CARGO_TERM_*` before sccache keys the compile.** This covers lanes, IDEs and other repos that export them. `tests/test_goh_rustc.py` runs a private sccache server: with `CARGO_TERM_COLOR` exported, a build straight to sccache gets 0 hits and a build through the shim hits; a pass-through shim fails both tests. The wrapper is not wired machine-wide yet: `~/.zshenv` exports `RUSTC_WRAPPER=sccache`, which outranks `build.rustc-wrapper`.
