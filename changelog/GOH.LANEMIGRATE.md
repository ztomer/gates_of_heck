* GOH.LANEMIGRATE: only the code of record migrates the shared state databases. On 2026-11-23 `goh land --check` run from lane worktrees applied the lanes' unlanded migrations to the real goh.db, and main's goh then refused every write to it until those lanes landed, so land rows and durations stopped. The code of record is the primary checkout (its `.git` is a directory) or an install with no git; a linked worktree (a lane, a landq slot running a land's pre-step, the idle suite's tree) is not. Such a copy writes the shared goh.db or goh-cache.db only when the file already holds every migration the copy ships; otherwise it opens the file read-only and names the missing migration, and it never creates a missing one. A landed migration is applied by main's next run. Files outside the account's goh directories, such as a test's temp file, still migrate from any copy. The read-only warning for a file holding a migration this goh does not ship now names that migration and who applied it (it read "version 4 (applied [4]), newer than this goh's 6").
