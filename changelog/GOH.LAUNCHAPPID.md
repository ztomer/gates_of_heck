* `goh launch-app -b ID` / `--bundle-id ID` launches an app by its bundle identifier (`open -b`) with launchd's login environment; before it an id given as the TARGET was read as an app NAME (`open -a com.google.GeminiMacOS`), which fails (GOH.LAUNCHAPPID).
* `tui/launch.py` (`from tui.launch import launch_app, launch_argv`) is the one Python spelling of `goh launch-app`; goh's appstate hook launches through it, and no Python caller builds `$GOH_DIR/bin/goh launch-app` by hand.
* `goh bare-open` judges a Python argv list as argv: `["env", "/usr/bin/open", ...]` and `["nohup", "open", ...]` are findings, `env -i` is the clean launch by design rather than by accident, and a string that is an argument of another program (`["git", "commit", "-m", "open -a X"]`) is no longer read as a command line.
