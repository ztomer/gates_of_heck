* An older goh never writes a consumer a newer one installed (GOH.OLDINSTALL). Every `install.sh` records its release in the consumer's git config (`goh.installedRelease`, untracked: no commit, and it survives an agent's scratch HOME), and an `install.sh` whose own release (its CHANGELOG.md's newest `## vX.Y.Z`) is older refuses before its first write, naming both releases; `git config --unset goh.installedRelease` is the deliberate downgrade. The caller that put the retired goh_dir_repair block back into four consumers' tools/gate.sh (2026-11-14/15) was a session holding GOH_DIR at a HEAD export cut before the rollout, under an agent HOME whose export cache was never pruned, running the install.sh the stale-hook fix printed: structural.sh now names the live checkout's install.sh, never the export's.
