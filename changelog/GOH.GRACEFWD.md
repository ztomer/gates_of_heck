* **A grace-gated rule judges the forward-correct tree green on both sides of the date (`GOH.GRACEFWD`, found by EST.GRACEFIX).** `goh moving-tags` now reads shell scripts and Makefiles before 2026-11-23 (judging them only from it), so `GOH_MOVING_TAGS_MIN_REFS` declared at nine tenths of the post-grace count is green today instead of `read NONE`; and a reasoned `# moving-tag-ok:` over an image that moves only from that day (a release line such as `postgres:16`, or a script's image) exempts it before the day instead of reading as stale, so a fleet repo can pre-mark its images. Unmarked, such a site still passes before the day and is red from it.
* **`goh seed-add` writes an entry where its repository's other seeds live (`GOH.GRACEFWD`).** Routed by root commit to the repository the command runs in or one the estate registry names, an entry goes to that repository's own tracked `<kind>_seed.json` when it keeps its seeds tracked (a tracked seed file at its root, or CI that runs goh), and a duplicate in the private store moves out; every other entry goes to the store as before. Monitor's `floor_seed.json` entry had gone to the store, where its hosted CI cannot read it.
