* GOH.LANDQDB (L1): the land queue's requests move into goh.db. Migration 0007 adds `requests` (one row per request, keyed by the queue's realpath and the request stem, its `state` one of enqueuing, pending, running under a CHECK), `slot_owners`, `early` and the view `landq_v1`. `lib/landq_state.py` is the requests' one writer: a request keeps its name `<q>/<state>/<run>.json` (what `goh land --enqueue` prints and `--wait` takes), but the name is a key, never a file. Filing a request deletes the enqueue's pre-step marker in the same transaction, a move between states is one UPDATE, and the land record's write deletes the request in its own transaction, so a SIGKILL anywhere leaves a request in exactly one state. Proven red first on the files: a kill after the land record left the request in `running/` and `done/` (the next lander ran it again), and a kill after the enqueue filed left a dead enqueuer's marker beside the pending request, which the next reader recorded red as "enqueue died". Checkout slot ownership is a `slot_owners` row claimed in one transaction that reads the owner and the queued requests (was `link(2)` and a directory scan). The lander imports an older goh's request and owner files under `lander.lock` (`INSERT OR IGNORE`, each file deleted once its row reads back), and `goh_db.py landq-export` writes the rows back as those files for a revert. `pre/*.record` stays a file for now.
* GOH.LANDQDB: the live lander was proven through goh.db once L1 landed: a land, a `--cancel` in its pre-step, and a bisect probe (a batch of two whose second item, a planted red, never landed).
* GOH.LANDQDB: `goh state retire landq` retires an older goh's land queue files: a stray request file under `enqueuing/`, `pending/` or `running/` goes in as its `requests` row and an `early/` file as its `early` row, under `lander.lock`, then is read back, archived and deleted, and each directory goes once empty. A row already there (a land in flight) is never rewritten, a run whose land is recorded is not queued again, and while a lander holds its lock every file is kept.
* GOH.LANDQDB: the land queue's request files are read by nothing. The lander no longer imports an older goh's `pending/`, `running/` or `enqueuing/` files at its start (`goh state retire landq` does), `lib/state_bounds.py` no longer lists those directories, and the state seam's land queue allowlist is empty. `goh_db.py landq-export` (L1's way back, writing the rows as those files) is gone from main: the revert branch carries its own copy.
* GOH.LANDQDB: `lib/lock_order.tsv` lists `lib/state_retire_landq.py` as a taker of the lander lock, and `lib/landq_state.py` leaves the base table, because nothing loaded before every test imports it now that the export is gone.
