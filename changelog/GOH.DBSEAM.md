* GOH.DBSEAM: the foundation of goh's move to SQLite. `lib/goh_db.py` (goh.db, durable state, `GOH_DB`) and `lib/goh_cache_db.py` (goh-cache.db, disposable caches, `GOH_CACHE_DB`) are the one door to each file, over `lib/db_core.py`: WAL, a busy timeout per file (`GOH_DB_BUSY_MS` 30 s, `GOH_CACHE_DB_BUSY_MS` 2 s), migrations as `lib/goh_db_schema/NNNN_name.sql` and `lib/goh_cache_schema/NNNN_name.sql` applied by set difference (a lane's 0003 landing before another's 0002 no longer strands 0002), and each write's lock wait in `GOH_TIMINGS`. Every file keeps its version in `PRAGMA user_version` and a `meta` table (db, schema_version, created_by, last_migrated_by, created_at); an older goh opens a newer goh's file read-only and never migrates it down. `lib/db_bounds.py` bounds every table by days, rows and bytes (`-- bound:` headers) and each file by a budget (goh.db 256 MB, goh-cache.db 2 GB): a history table's oldest rows move to `goh-archive-YYYY.db`, a cache table's are evicted; `lib/state_bounds.py` sweeps and checks both. Both databases are the innermost locks of `lib/lock_order.tsv`; under the test suite, opening the real home's goh database raises. `tests/test_state_seam.py` names every file that still reaches a store the plan moves, as a ratchet that ends empty.
