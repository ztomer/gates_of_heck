* **The rust coverage cache holds its byte budget while runs are live, and no coverage scratch outlives its run (EST.FSEVENTSCHURN).** fseventsd at 100% (2026-11-14) was goh's coverage gates rebuilding instrumented builds; the per-crate key behind it went in GOH.COVSHAREDBUILD, and this closes what was left. The budget (`GOH_COV_CACHE_MAX_GIB`) was checked only when a run started and when it ended normally: the build a run made in between, and every failing run, went unchecked, and a build whose run had just finished was spared for 10 minutes whatever its marker said (the cache held 10 builds, 8.5 GiB against 8, on 2026-11-15). It is now checked after each instrumented build and when the run exits, pass or fail, and an entry whose `.goh-running` names no live pid is idle at once; the decision is made under the marker's lock, which `mark` takes too, and the entry is renamed away before it is deleted, so no run can start building in a directory being removed (`gates/_head_cache.py`). A run's `.profraw` profiles and the report's `cov-view` hard links, which kept an evicted build's executables on disk where no budget counted them, are deleted by an EXIT trap; `lcov-parts` (the run's record) stays. On a private server workspace, all 29 crates cold, per-crate key (before GOH.COVSHAREDBUILD) against this tree: cache 29 builds, 3.35 GiB -> 1 build, 2.27 GiB; 539.6 -> 448.5 CPU s; 170.7 -> 120.9 s wall; fseventsd 24.8 -> 16.3 CPU s over the run; scratch left behind 359 files -> 0; every crate's report identical.
