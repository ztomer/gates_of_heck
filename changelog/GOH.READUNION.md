* GOH.READUNION: a test's carried verdict no longer loses what the test read. When one run answered for part of a test file (a pre-step's slice, the judges' half of a set, an enqueue's owed tests, the Linux worker's share) and a carry for the rest, the tree's record kept one run's reads of the file, so a later change to a file only the carried tests read carried them green. Over the 80 suite records of 2026-11-24 and 25, 29 dropped reads of tests they carried (265 file lists, 795 paths) and 15 carried 259 test verdicts (137 tests, 10 files) across a change to a dropped path; none of those tests was red in a land or a full run since. Every join of reads is now one (`lib/read_sets.py`): the lists are united, a file any of whose passed tests nobody watched is left out (so no carry takes it), and a record kept by an older goh is believed for none of its reads, so the first land after this one runs the tests it would have carried.
* GOH.READUNION: a Linux worker's share now says what its tests read and how many it collected (`tests/_shard_run.py`, in its junit). A share that did not finish (its pytest workers died: exit 1, one failure per crash, the rest never run) runs on the Mac, every test of it, in the land pre-step and in the gate; before, only the failures were run again, and a new test in the share could land having run nowhere.
