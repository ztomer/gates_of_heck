* GOH.DURATIONSDB: the suite's timing tables move into goh.db (migration 0006). `test-durations.json` and its `.poles` / `.poles-cpu` siblings were whole files every top-level run read, merged and replaced with no lock, so two runs ending together kept one run's readings; now each run inserts one row per reading (`readings`), with its prunes (`pruned`) in the same transaction, and readers see the `durations` view, each test's newest unpruned reading (`lib/durations.py`). Each (kind, test) keeps its newest 5 readings, within 30 days. The remote split's rates and its linux-unsafe ledger move beside them (`duration_kv`). The JSON files are imported once, by sha256, on the first write, and read until then.
* GOH.DURATIONSDB: a goh older than a goh.db's newest migration no longer calls that migration's tables unbounded (a goh without 0006 named readings, pruned and duration_kv as having no `-- bound:` header); the newer goh's own check judges them, and a stray table in a file of this goh's own version is still named.
