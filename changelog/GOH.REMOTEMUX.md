* The land pre-step's worker share no longer falls back to the Mac when the shared ssh multiplexer fails (GOH.REMOTEMUX): `mux_client_request_session: send fds failed` (ssh exit 255, before the remote command starts) now costs one fresh connection (`ControlMaster=no`, `ControlPath=none`) and the rest of that run stays off the multiplexer; any other exit 255 is still a fallback. Each share's outcome (`remote`, `failed` or `fallback` with its cause: busy, mux, unreachable, dropped, off-pin, skips, scratch, in-flight, no-junit, start, other) reaches the land record as `pre_run.remote`, and `goh land --report` counts the shares, the fallbacks by cause and the fresh connections per row. Of the 8 fallbacks in the queue's logs before this change, 7 were a busy worker (load over 6.0) and 1 the multiplexer; none was the Python version drift.
- The pre-step's worker-share reader lives in lib/landq_remote.py `took`, keeping lib/land_prestep.py under the 450-line headroom after GOH.PRESTEPDETACH grew it.
