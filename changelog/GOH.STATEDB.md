* GOH.STATEDB (S1): goh's land records move into goh.db. Migration 0002 adds `lands` (one row per land, keyed by the queue's realpath and the request stem, its summary columns beside the whole record), `land_guards`, `red_causes`, `selection_misses` and the view `lands_v1`, each under a `-- bound:` header. `lib/land_records.py` is the records' one door: the lander writes the row and then the `done/` file (still written for the loop's readers and old HEAD exports until the delete commit), readers read every row plus any `done/` file with no row, and `import_done` brings today's files and `red_causes.json` in with `INSERT OR IGNORE` and an `imports` row. `goh land --report` and `goh land-reds` read through it, and their output on the 536 live records imported into the table is byte-identical to their output from the files. The lander's `record` writes the row, and every reader of the land records reads through the door: the report, land-reds, attempts, flake retries, the e2e and profile chains, admission replay, diffcov carry, the batch size history, the pre-step window, selection-miss replay, `land --check`'s history, `--status`, `--wait` and the alone rule. `state_bounds` imports the `done/` files before their 14-day bound prunes them, so a record an old HEAD export wrote is a row before its file goes. The two ledgers follow: `land --check`'s learned refusals go to `land_guards` and the selection misses to `selection_misses` (each body once per queue), and the import brings `guards.jsonl` and `selection_misses.jsonl` in beside the records.
* GOH.STATEDB (wave 3): `goh state retire [STORE...] [--dry-run]` (`lib/state_retire.py`) retires a moved store's files: it imports what they hold (INSERT OR IGNORE), reads every record back from goh.db, copies the files under `<state>/retired/<YYYY-MM-DD>/<store>/` and deletes them only when each record read back equal; one unequal record keeps the whole store. `goh state stray` names a retired store's file still on disk. A reader of a moved store raises `goh_db.Unknown` when there is no goh.db (`goh_db.known()`): unknown, never zero. The hook ledgers (S4) go first: `lib/hook_ledgers.py` reads and writes goh.db alone, its file import moves into the retire command, and the seam's `hook ledgers` entries are empty.

* GOH.STATEDB (wave 3, S2): goh ship's records live in goh.db alone. `lib/ship_status.py` save writes only the `ships` row and the install step only the `ship_pins` row (no result file, no `.pins.json` sidecar; save still makes the result's directory, where the step logs and the lock live), and `lib/ship_records.py` reads the rows alone. `goh wait ship` waits on the row. * GOH.STATEDB (wave 3, S1): a land's and a ship's record fail loudly. Each is a goh.db row with no other home, so `goh_db.must` writes it, tries once more after a second, and then says the failure and raises it: the lander leaves the request queued for the next lander instead of dropping it, and a ship fails instead of ending with no record. Before, `lib/land_records.py` wrote "no goh.db row" and relied on the `done/` file, and `lib/ship_status.py` save said the same and lost the record (the class of GOH.SHIPNORECORD).
