* **`lib/goh-rustc` keeps the build dir's path out of sccache's Rust keys for proc-macros and build-script output (GOH.SCCACHEPATHS, design GOH.CACHEEVICT section 4, F2 and F3).** A proc-macro dylib's install name was its absolute build-dir path, so every crate using it missed in each new build dir (8.0% of the machine's Rust misses); on macOS the wrapper now links proc-macros with `-Wl,-install_name,@rpath/lib<crate>.dylib`, a name rustc never reads (`GOH_RUSTC_OS` is the seam). `include!(concat!(env!("OUT_DIR"), ...))` put the build dir's path in a crate's dep-info and rlib, so it and its dependents missed too (5.4%); the wrapper points `OUT_DIR` at a copy in `GOH_OUTDIR_STORE` named by a hash of every file's path and bytes, cloned with `cp -c` where it can, and leaves `OUT_DIR` alone when the copy fails. Measured on a private sccache server (`tests/test_goh_rustc_paths.py`), four crates at one shared path under a top crate built from a fresh checkout and build dir each time: straight to sccache the second build hit 0 of them, through the wrapper 3 of 3 (od, usepm, useod); a changed proc-macro missed only its user, a changed build-script output only od and useod, and a repeated build stayed fresh. Red runs: the old wrapper 0 of 3; install name off 2 of 3; OUT_DIR off 1 of 3; a hash of the bytes alone shared `ab`+`` with `a`+`b`. The workspace member's own cwd still misses (cause E, 2.2%): sccache 0.19 has no Rust path remap, and `SCCACHE_BASEDIRS` stays unset, it is C-only and gives false C hits with the preprocessor cache.
