# docs/config.md — every `GOH_*` key

Single schema. CLI flags beat env/.gatesrc where both exist. Unset means
"gate default or skip" per row — never a silent pass on a missing floor
(coverage gates exit 2 when no floor is stated anywhere).

## Structural (`gates/structural.sh` + `checks/`, native: `bin/goh`)

| Key | Default | Meaning |
|---|---|---|
| `GOH_BIN` | unset | Explicit path to the native `goh` binary. Set-but-missing is reported once and the gate REFUSES (there is no other tier since Phase N3); unset resolves the build of the commit the gate runs from (`bin/by-stamp/<sha1 of its source stamp>/goh`: a current `bin/goh` is adopted there, a commit the checkout has moved past is built there with `build-goh.sh --rev`), then `goh` on `PATH`. |
| `GOH_NO_NATIVE` | unset | **Retired** (Phase N3). It selected the Python checkers, which are gone; a run that sets it is told so and runs the binary. Drop it from CI. |
| `GOH_SKIP_BUILD` | unset | For `install.sh`: install hooks without building `bin/goh`. |
| `GOH_MAX_LINES` | unset (check skipped + warn) | File-length cap. Set `500` in every repo. `off` records a deliberate no-cap (an info line instead of the warning) for a repo whose files are long by design; say why in a comment beside it. |
| `GOH_EXPORT_KEEP` | unset | Ignored files the pre-push export must carry (space-separated, repo-relative), e.g. a compile-flag marker the manifest reads. The gate runs on a clean worktree of the pushed commit (`gates/push_gate.sh`); tracked files are always there, ignored ones only if named here. The proven cache keys every step on these files' content, so a green step that REWRITES one moves its own key and is never recorded: the runner names repo, step and path, and is red unless the tracked top-level `kept_rewrite_allow.json` carries that step and path with a reason (`lib/kept_rewrite.py`; a stale entry is red too). |
| `GOH_PUSH_WORKTREES` | `~/.cache/goh/push` | Where `push_gate.sh` checks the pushed commit out. Never the temp directory: SwiftLint's baseline matches nothing under `/private/tmp` or `$TMPDIR` and everything under `/Users` (measured 2026-09-21). |
| `GOH_PUSH_LOGS` | `~/.cache/goh/push-logs` | Where `push_gate.sh` tees each run's output. A green run deletes its log; a red one keeps it and prints the path (newest 20 kept), so a refused push never loses its evidence. |
| `GOH_TAG_VERSION_SOURCES` | `file:VERSION cargo:Cargo.toml` | Version sources `push_gate.sh` checks a pushed `refs/tags/v<semver>` against — space-separated `kind:path`. Kinds: `file` (first meaningful line), `cargo` (`[workspace.package]`/`[package]` `version`), `swift` (any string constant whose value is `x.y.z` — a SwiftPM package that declares its version in source, where the constant is usually named `marketing` or `version` and is usually accompanied by a build number that is NOT a release number; `swift:` returns EVERY release-shaped constant, so a file declaring two different ones still fails rather than one being picked). `plist` (`<key>`/`<string>` pairs in an Apple bundle `Info.plist`; without it a bundle's version is unreadable, because `file:` reads the XML **declaration** `<?xml version="1.0"…?>` as the version and reports a correct release as a mismatch — measured on ZeroThunder's `v2.10.0`, which no other kind could check) `pyproject` (the `[project] version` a Python distribution declares; without it a packaging-only repo has no readable source and `file:` reads whatever the first meaningful line happens to be), `xcodegen` (the `MARKETING_VERSION:` key in an XcodeGen `project.yml`, and only that key: the same file pins package and Swift versions in the same shape) and `gradle` (`versionName` in a `build.gradle(.kts)`, Kotlin or Groovy spelling, and only that name: dependency coordinates carry versions too; measured on koffee_big's `v2.11.5`, whose release was declared in both files and readable by neither) and `changelog` (the newest `## vX.Y.Z` heading of a CHANGELOG.md: a repo whose version IS its tag, as goh's is since GOH.SHIPRELREUSE, declares the release only in the stanza its release commit cut). A `path` may be a glob, expanded against the TREE AT THE COMMIT; scope it (`cargo:crates/*/Cargo.toml`) rather than `**`, which sweeps `vendor/` and invents findings about crates this repo does not ship. Empty or all-unknown is exit 2, never a pass over nothing. `goh tag-version --root X` and `goh lock-version --root X` read it from the environment, else from X's own `.gatesrc` (`gatesrc::repo_setting`), so a caller that sourced nothing gets the repo's answer. |
| `GOH_STEP_TIMEOUT` | **1800** | The wall-clock CEILING on every `goh_step` in every toolchain gate (`structural.sh`, `rust_gate.sh`, `py_gate.sh`, `swift_gate.sh`) and on every step the native `bin/goh` delegates. Printed on each step line; `0` opts out and says `UNBOUNDED` rather than looking identical to a bounded step; non-numeric is exit 2, because a typo'd ceiling must not silently leave the step unbounded. `goh_step` had **no** ceiling while `local_ci.sh` did, so one hang had two answers; the native tier had none either and now routes every delegated step through `lib/bounded_run.py`, so all three paths share one implementation of the bound. Judged via `--stall` (progress = advancing process-group CPU or runnable threads) and `--cpu-timeout`, with a wall-clock backstop. |
| `GOH_STEP_GRACE` | 5 | Seconds between the process-group SIGTERM and SIGKILL when a ceiling expires. |
| `GOH_EXCLUDE` | unset | Regex on repo-relative paths that are NOT OURS TO RE-STYLE: vendored third-party source, generated code. **Exempt from**: the emoji scan, the length cap (with `GOH_LINE_EXCLUDE`), shell lint, early-exit pipe, code after exec, bare hook index, release quiet, BSD-only mktemp, bare open, run paths, hedged plural, hand-rolled TUI mark, git deadline, dead port, bare python, layer parity (an excluded file is no language the repo holds), home paths, kill-by-name, unreaped spawn, subprocess-stdin, md-links, claim-derivation, roadmap (the plan files besides `GOH_ROADMAP` it looks for), `#[allow]`/`#[expect]` and emptiness asserts (commit and push), and `--each-crate`'s per-crate fmt/clippy/test/coverage (an excluded crate is gated through whatever first-party crate builds it; the pattern is matched against the crate's MANIFEST path, `crates/vendored-rs/Cargo.toml`, so `'^crates/vendored-rs/'` excludes it -- until 2026-10-08 it was matched against the bare directory, where a trailing-slash pattern never matched, and by `grep -E`, which refused a look-ahead; `rust_gate.sh --each-crate --list` prints what is left), and `py_staged.sh`'s ruff, staged and `--all` alike (a vendored `.py` is not ours to re-format; until 2026-11-18 only `--all` dropped it, so a commit refused the vendored file its push exempted -- GOH.PYSTAGEDEXCLUDE), and `py_lint_ceiling.py --seed` (an excluded file's findings are no debt the repo carries). **Every entry point reads it the same way**: the structural gate, a direct `goh <check>` or `goh.sh <check>` given no `--exclude` (it reads the repo's `.gatesrc`; `--exclude ''` opts out), and the R3 estate sweep over a consumer's corpus. Until 2026-10-08 a direct check ignored the file, so `goh.sh md-links` in `app_updates` reported a vendored dead anchor its own gate exempts. The AMBIENT environment never counts: an inherited `GOH_EXCLUDE` is not the repo's declaration. **Never exempt from the secrets scan**, by construction: `goh secrets` takes no exclusion at all -- nor the checkout-credentials scan (`goh checkout-credentials`), whose one escape is `# persist-credentials-ok: <reason>` on the step, nor the tap-write scan (`goh tap-writes`), whose one escape is `# tap-write-ok: <reason>` on the line, nor the moving-tag scan (`goh moving-tags`), whose one escape is `# moving-tag-ok: <reason>` on the reference -- what a build pulls is not a style, vendored or not -- nor the workflow-pin scan (`goh workflow-pins`), whose one escape is `# workflow-pin-ok: <reason>` on the reference -- what CI runs on is not a style. A path pattern written for style cannot say anything about a leak, and until 2026-10-08 this one silently reached the credential scan too -- `app_updates` excluded a vendored crate and 57 of its 63 staged files went unscanned (ztools had grown a separate vendor secrets step to cover the same hole). There is deliberately no second key for "vendored": with two, `GOH_EXCLUDE` could still drop the scan; with none, nothing can. A real vector in vendored code is fixed or carries `secret-ok: <reason>` on its line, as first-party code does. An exclusion that leaves a commit with no Rust of its own to scan is nothing to judge, not a blind scanner: the "matched NO compiled source" refusal fires only at full scope and only on a `Cargo.toml` the exclusion leaves in scope. **Anchor it.** The match is `re.search`, so `'vendor/'` is a SUBSTRING test: it exempts `rust/src/myvendor/a_tests.rs` exactly as it exempts `vendor/camoufox-rs`, silently. Write `'^vendor/'`. Measured 2026-10-04 on `ztools`, which declares the unanchored form: with it, 106 first-party test files stay in scope and a violation planted in one is still red — so it is narrow in effect today — while the same violation at a path merely *containing* `vendor/` is exempt with no output at all. |
| `GOH_LINE_EXCLUDE` | unset | ADDITIVE to the length check only. Effective length exemption = `GOH_EXCLUDE` ∪ `GOH_LINE_EXCLUDE`. Paths named only here are still emoji-scanned. |
| `GOH_LINE_BASELINE` | unset (check skipped + warn when `GOH_LINE_EXCLUDE` is set) | Path to the repo's shrink-only ratchet baseline. Enables two checks: every `GOH_LINE_EXCLUDE` entry over the cap carries a ceiling there — an exemption from the cap is not an exemption from every bound — and the ratchet itself: each listed file is measured (`wc -l`) and may not exceed its ceiling. Lower a number when a split lands; never raise one to absorb growth. Format: `<lines><tab><path>` per line (`#` comments) or a JSON object mapping path to lines. |
| `GOH_LINE_UNBOUNDED` | unset | Regex naming the `GOH_LINE_EXCLUDE` entries that legitimately need no ceiling — captured or vendored material that must stay emoji- and secret-scanned but is not ours to split. State the reason beside it in `.gatesrc`. A pattern matching no tracked file FAILS. |
| `GOH_ALLOW` | unset | Extra permitted characters (regex chars, spaces stripped). Keep empty unless the repo genuinely needs it. |
| `GOH_SKILLS_CORPUS` | unset (check skipped) | Set to `1` in a repo that IS an agent skills corpus (`~/.claude/skills`, `~/.agents/skills`) to run `goh skills`. Opt-in rather than auto-detected, so a repo that merely SHIPS example skills is unaffected. |
| `GOH_CROSS_REPO_ROOT` | unset (not needed) | For `gates/push_gate.sh`, and set BY it: the real checkout of the repo being pushed. The export worktree holds the pushed commit's TRACKED files, so a repo whose evidence is its sibling repositories — a metarepo, whose children are separate repos rather than submodules — has none of that evidence in the export, and every cross-repo citation resolves to nothing. Measured 2026-10-03 on `games`: 9 findings on a commit whose checker exits 0 in the working tree. A checker may read this ONLY for citations that name a child; it is deliberately not a symlink of the children into the worktree, which would put sibling sources inside the parent's scanned tree and fail a parent push on a child's finding. The worktree's isolation is untouched: it guards a repo's OWN files, and those still come from the worktree. |
| `GOH_SKILLS_ROOT` | the repo root | Corpus root, when the skills tree is a subdirectory rather than the repo itself. A root OUTSIDE the repo is skipped by name at `--staged` (no part of the commit) and, when it is its own repository, judged at ITS LAST COMMIT at full scope -- never its working tree, which another session may be mid-edit in (C2). A root in no repository is read as it stands. |
| `GOH_NO_HOME_PATHS` | unset (check skipped) | Set to `1` to run `goh home-paths`: no `/Users/<x>/…`, `/home/<x>/…`, `~/Projects/…` or `$HOME/Projects/…` in any tracked text file (a `${VAR:-default}` expansion is derived, not hard-coded, and passes). A path that must stand carries `path-ok: <reason>` on the line or above. Opt-in per repo — turn it on once the tree is clean, never red in twenty places at once. Same `GOH_EXCLUDE`. |
| `GOH_PYTHON_FORMATTED` | unset (check skipped) | Set to `1` to run `check_python_formatted.py`: every tracked `.py` must match what `ruff format` produces, using the rule set the repo declares in `pyproject.toml` / `ruff.toml`. Opt-in per repo, both scopes: `--staged` judges the INDEX blobs of the staged `.py` files (`ruff format --check --force-exclude --stdin-filename`) and reformats nothing, so a commit is refused for its own bytes only; full scope judges the tree. (It was full-only until v0.21.0, and two unformatted files passed pre-commit and refused the v0.20.0 push.) The checker reads ruff's settings from the tree it runs in, so with no configuration it answers from ruff's defaults and from the directory it was launched from — which is why the flag exists rather than a default-on step. It refuses to skip when `ruff` is absent: an uninstalled formatter is a missing gate, not a pass. WHICH ruff is the Python gates' runner rule (`gates/_py.sh`): `GOH_PY_RUNNER`, else a TRACKED `uv.lock` runs `uv run --frozen ruff` (`GOH_PYTHON_VERSION` adds `--python`), else a `.venv` runs `.venv/bin/python -m ruff`, else `ruff` on `PATH` -- so the format verdict is the repo's pin, never the launching shell's. A tracked lock with no `uv` on `PATH` is a named refusal, not a fall back to `PATH`'s ruff. |
| `GOH_CLAIM_DERIVATION` | unset (check skipped) | Set to `1` to run `goh claim-derivation`: a **MARKED** number in prose is re-derived from the tree. Three adversarial reviews of the games estate converged on one class (2026-10) — `roadmap_state.py` claimed "64 declared gates" against 70 in `verify.py`, `check_mcp_server.py` claimed "477 lines and 18 characterization tests" for 321 and 20, `gaf/README.md` claimed 86 files / 1059 tests for 101 / 1732, and each was found by hand at hours apiece. **The claim form is explicit, and the looser rule was rejected**: a claim is read only when the number AND the thing it counts are both in backticks (this estate's existing convention that a backtick means "this is the evidence"), or when the line carries a leading `claim:` marker. A bare number beside a path is prose, because reading bare numbers means reading English — a gate cannot tell an inventory from an incident, a current claim from a quoted one, or a count from a version, and it is wrong LOUDLY when it is wrong. **Four units, each derived exactly**: `lines` (`awk 'END{print NR}'` — not `wc -l`, which reads a file with no final newline one line short), `tests` (test functions by `ast`, a parametrised case counting once), `gates`/`steps`/`checks` (elements of a NAMED module-level list, by `ast` — never a line regex, which is what read 64 against 70), and `files` (the length of `git ls-files`'s own answer for `DIR/*.EXT`). Every finding prints the command that re-derives the truth, and `--probe` EXECUTES those commands against fixtures, so a finding a reader cannot check cannot ship. Survivors go in `claim_derivation_allow.json` at the repo root: one claim in one file each, with a `reason` and a `status` (`legitimate` or `unreviewed`); **a stale entry fails**, and the key is the claim itself, whitespace collapsed, not its line, so neither `ruff format` nor a re-wrapped paragraph can revoke an exemption while a changed number does. Opt-in per repo, seeded first: this lands RED in every repo in the estate, because every repo in the estate has this defect, and a gate that goes red in twenty places on the day it lands is a gate that gets disabled. Fenced blocks are examples in every text file, and in Python a non-docstring string literal is data rather than prose — that is where a checker's own fixture lives, and a gate that cannot express its test cases cannot be tested. Same `GOH_EXCLUDE`. |
| `GOH_REQUIRES_CALL` | unset (check skipped) | A repo-relative TOML file of rules for `goh requires-call`: a Python file that CALLS X must also CALL Y, read from the AST (`ruff_python_parser`), so a docstring naming Y never satisfies it. Each `[[rule]]` has `name`, `why` (printed with every violation), `files` (globs), `calls` (the trigger; omit it and every matched file is bound), `must_call` (each a `module.function`, resolved through the file's own imports, or a bare name: any call whose last name it is; either, or `*` for any callee, may name string arguments, `cli("config-set")` or `*("theme", "--id")`, which must sit side by side among the call's positional arguments, a list or tuple literal spread in place -- an argument built at run time never matches) and an `[rule.exempt]` table of `"path" = "reason"`. An exemption goes STALE, and fails, when its file is gone, no longer calls X, or now calls Y; a rule that finds nothing to judge is exit 2 (the pattern moved). From a private Swift app's `check_probe_placement.py` and `check_probe_courtesy.py` (2026-10-08). |
| `GOH_NO_KILL_BY_NAME` | unset (check skipped) | Set to `1` to run `goh kill-by-name`: no `pkill` or `killall` by name, and no `pgrep`/`pidof` feeding a `kill`, in tracked code and scripts (a `pkill -P`/`-g`/`-s` is owner-scoped and passes). A name matches processes the caller does not own. Survivors go in `kill_by_name_allow.json` at the repo root: one call in one file each (in Python the whole statement, whitespace and trailing commas ignored, so a reformat keeps it; an entry holding only part of the call still matches and is named for re-keying), with a `reason` and a `status` (`legitimate` or `unreviewed`); a stale entry fails. Opt-in per repo, seeded first. Same `GOH_EXCLUDE`. |
| `GOH_NO_PRIVATE_NAMES` | unset (check skipped) | Set to `on` in a PUBLIC repo to run `goh private-names`: no tracked line or path names a private repository. The names are the owner's, read from the private seed store's `private_names.txt` (the estate seeds' own directory, `~/.local/state/goh/seeds` by default; one name per line, `#` comments, matched case-sensitively at word edges; a side where the entry ends in a separator -- `word/`, `/word`, a backticked `` `word` `` -- needs no edge, so a repository named by an English word is listed by its path forms and the prose word stays free), never from a tree; a machine with no list (a GitHub runner) says `not judged` on a warning line. |
| `GOH_RUN_PATHS` | unset (check skipped) | Set to `on` to run `goh run-paths` (`crates/goh/src/runpaths.rs`, GOH.CLASS.CHECKOUT part 2): a temp, lock or stage name (`.lock`, `.staging`, `.tmp`, `XXXXXX`, `mktemp`, `mkstemp`, `mkdtemp`, `NamedTemporaryFile`, `TemporaryDirectory`) on a line that roots it at a work tree (`$PROJECT_ROOT`, `$repo`, `$root`, `$top`, `$main`, `$wt`, `$PWD`, a positional `$1`..`$9`; Python `repo /`, `Path.cwd()`, `dir=repo`; Rust `repo.join(`), a path in such a root's `build/`, or a `git write-tree` (it writes the shared index under `index.lock`) in a shell, Python or Rust source is red. The one place these are minted is the run-path helper (`lib/run_path.sh`, `lib/run_path.py`, `crates/goh/src/run_path.rs`), which the scan does not read; tests, comment lines and a Rust file's `#[cfg(test)]` tail are not read either. Escape: `run-path-ok: <reason>` on the line or the line above. The sites standing when it landed are seeded in `run_paths_seed.json` (`crate::estate_seed`); it landed empty. goh's own `.gatesrc` sets it; the shapes are goh's, so it is opt-in. |
| `GOH_NO_EARLY_EXIT_PIPE` | unset (the seed holds the tree) | `goh early-exit-pipe` runs in EVERY repo as a structural step: an early-exit consumer reading a pipe in any shell source -- `grep -q`/`--quiet`/`-l`, `grep -m`/`--max-count`, `head`, an awk program that calls `exit` outside `END`, a sed script with `q`/`Q`. The consumer closes the pipe, the producer's next write dies of SIGPIPE (141), and pipefail makes that the pipeline's status: a match reads as a miss, depending on load (a private server workspace's deploy.sh read a RUNNING service as absent, 2026-10-08). Unset, the step refuses a NEW finding at `--staged` (one the file's HEAD blob does not carry, matched on the consumer's text, so a moved line is not new and an edited one is), and at full scope judges each file against `early_exit_pipe_seed.json`, a per-file count that may only fall: an unseeded finding fails, a file over its count fails, and a file under it fails until the seed is lowered (BACKLOG 6.9; it used to name existing ones and pass). `goh early-exit-pipe --seed` writes the seed a repo adopts with; a pipe that is genuinely safe (its producer cannot outlive the reader) is said there. Set to `1` to ignore the seed: every finding fails, at both scopes. Fix shape, printed per finding: `out="$(producer)"; grep -q PAT <<< "$out"` (or `head -n1 <<< "$out"`, or `[ -n "$out" ]`); only a status something READS is a finding, so a pipeline ending `\|\| true`/`\|\| :` and a substitution used as an argument (not assigned) pass. Scope: every shell source -- `*.sh`, `*.sh.tmpl` (the template an installer is regenerated from), `*.bash`, `*.zsh`, and sh/bash/zsh/ksh/dash shebangs -- and NOT gated on the file's own pipefail line, because a sourced library runs under its caller's (a private server workspace's install-lib.sh and install.sh.tmpl both slipped a scan that read only `*.sh` files saying "pipefail"). Same `GOH_EXCLUDE`. |
| `GOH_SUBPROCESS_STDIN` | on | Unset or `on` runs `goh subprocess-stdin` in the structural pipeline at both scopes; only a written `off` skips it, so an opt-out is a decision in the repo's own file, the way `stdin=None` is at a call. **On by default since 2026-10-13** (BACKLOG 3.4), ahead of the estate sweep, by the owner's ruling that goh ships a check and each consumer clears its own debt in its own session: a repo with undeclared calls reads red at its next commit (996 findings in 17 of 34 repos on 2026-10-09; 15 rows remain, BACKLOG Downstream). Any other value is exit 1 NAMING THIS KEY, never a silent off. `goh subprocess-stdin` run by hand ignores it. A repo clears the red by declaring each call, or with `goh subprocess-stdin --seed` (one commit of its own, over committed Python): today's findings become `unreviewed` entries in `subprocess_stdin_allow.json`, or `subprocess_stdin_allow.d/seed-NN.json` past 400; a reseed keeps reviewed entries as written and drops stale ones. |
| `GOH_SUBPROCESS_STDIN_MIN_CALLS` | unset (no floor) | **Full scope only.** `goh subprocess-stdin` runs as a structural step unless `GOH_SUBPROCESS_STDIN=off`: every tracked `.py`'s process calls must name `stdin=` or `input=`, read from the AST (`ruff_python_parser`), because a child that inherits a stdin it did not ask for HANGS rather than fails -- `ZeroThunder`'s bare `md5sum` probe hung the games metarepo's claims gate on 2026-10-05. The rule is uniform rather than a list of tools that read stdin, because that list rots; `stdin=None` is legal and means "inherit, on purpose", so inheriting is a decision someone wrote down. The declarable calls are `subprocess.{run,Popen,call,check_call,check_output}` and `asyncio.create_subprocess_{exec,shell}`; `subprocess.{getoutput,getstatusoutput}` and `os.{system,popen}` are REFUSED outright (no keyword exists), and a call through `**kwargs` is a finding -- a static read cannot see what the mapping holds. One level of attribute only: `a.b.run()` is deliberately not followed, because reaching through an attribute never resolved is how a port invents findings nobody has to fix. **This key is the floor that catches the fourth vacuous pass**: a scan that stopped seeing calls. Below it the step is red and says the scan lost its subject; a value that is not a whole number is exit 2 NAMING THIS KEY, never a floor of zero. It is full-scope-only because at `--staged` the listing is the files this commit brings, so a commit touching one helper would be red against its own scope -- while the stage that matters (did this commit ADD an undeclared call) is exact at both scopes. The floor is per-repo because a hardcoded one is wrong everywhere else. Survivors go in `subprocess_stdin_allow.json` at the repo root, or `subprocess_stdin_allow.d/*.json` beside it when that file would go over `GOH_MAX_LINES`: one entry, ONE call site, with a `path`, `call`, `line`, `reason` and `status` (`legitimate` or `unreviewed`); **a stale entry fails** (the finding is gone, the file is gone, or the call's text changed), and a malformed allowlist is a PROBLEM, never an empty list -- a gate cannot disable itself by corrupting its own exemptions. `line` is the call itself (whitespace and trailing commas ignored), so `ruff format` reflowing it across lines cannot revoke a judgement, and changing or deleting the call does; an older entry holding the call's first line still matches the call that contains it. A missing `status` counts as `unreviewed` debt and is printed on the passing line. `GOH_SUBPROCESS_STDIN_MIN_CALLS` unset means no floor; the step's other three vacuous-pass modes (no Python at all, every `.py` excluded, a `.py` it cannot parse) each have their own verdict. Same `GOH_EXCLUDE`. |
| `GOH_BARE_PYTHON_SCOPE` | unset (hooks and `tools/gate.sh` only) | Regex on repo-relative paths ADDED to the scope of `no bare python in a hook or gate` (`crates/goh/src/barepy/`). The default scope is what every repo has -- `.githooks/*` and `tools/gate.sh` -- but a repo's local CI and build scripts are the same class: a person or a gate runs them, and a bare `python3` there is whichever interpreter Homebrew linked last all the same. Which of a repo's scripts those are is the repo's to say, so it says it here, e.g. `'^(ci_local\.sh|build[^/]*\.sh|tools/[^/]*\.sh)$'` (ZeroThunder OW.42, 2026-10-31). Anchor it: the match is `re.search`. Only shell sources are read (a `.sh` suffix or a shell shebang), and `GOH_EXCLUDE` still wins over a path the scope names. A pattern that is not a regex refuses the step NAMING THE KEY (exit 2), never a silent "no widening". Raise `GOH_BARE_PYTHON_MIN_FILES` with it, so a scope that stops matching is red rather than clean. |

## Ship (`goh ship`, `tools/ship.py`, GOH.SHIP)

workflows, CI.PUBLIC): push through the pre-push gate -> the repo's release kit -> install -> the

**Calibration (GOH.ADAPTLANES2, 2026-11-17/18 UTC).** The 44 lines of `lane-starts.jsonl` (all `warn`) were joined to what each admitted lane then did: spawn `tool_use_id` -> the spawn's prompt in the coordinator's transcript -> its `Queue item <ID>` (the ledger now records `item`, so the next review needs no transcript) -> the first `landq/done/<ns-enqueue>-<ID>.json` enqueued after the spawn (`started`, `finished`, `slot_wait_s`, its log's `pre-land green in N s: waited W s, ran R s`) and the timing ledger's `land`/`push` rows (`wall_s`, `cpu_s`, `load1`, `load_end`). 24 distinct lanes joined (the rest landed elsewhere or were still running). A lane's WAITING is landq queue (`started` minus enqueue) + slot wait + pre-step wait.

* Load per core AT SPAWN does not predict the lane's own waiting: correlation 0.06; median wait 278 s under 1.5 per core (n=4), 937-1150 s at 1.5-2.5 (n=6), 19 s at 2.5-3.5 (n=3), 319 s at 3.5-5 (n=9). Spawn to enqueue is 5-80 min (median 29), so the load at spawn is long gone by the land. `goh land --report` for 2026-11-17: 843 min enqueue-to-start waiting against 1170 gate minutes, of which only 58 were slot waits: the waiting that lanes add is the land queue's.
* The load ceiling is therefore set where extra load stops buying work for the gates already running (101 green push/land rows over 60 s, binned by mean load per core over the run): a gate's cpu-s per wall-s is 2.55 / 2.82 / 2.77 at <1.5 / 1.5-2 / 2-2.5 per core, then 2.04 / 2.23 / 1.59 at 2.5-3 / 3-4 / 4-5; the median goh land wall is 650 / 641 s at 1.5-2.5, then 677 / 805 / 730 / 948 s at 2.5-3 / 3-4 / 4-5 / 5-7. Past 2.5 per core a new lane's work only stretches the gates in flight: `GOH_LANE_LOAD_PER_CORE=2.5` (was 2.0 by judgment). At 2.5, 23 of the 44 spawns would have been refused (31 at 2.0).
* Waiting tickets at spawn: 7 of 44 spawns saw a long-lane waiter; the 3 joined lanes among them waited a median 0 s (21 lanes that saw none: 418 s). The longest slot wait any joined land saw was 404 s, shorter than the shortest spawn-to-enqueue gap (5 min): one waiter clears before the new lane's first gate asks. Two waiters are a full queued round of both slots: `GOH_LANE_MAX_WAITING=1` (was 0).
* Disk: free space on `~/.cache` ranged 96.3-118.9 GiB across the 44 readings (a 22.6 GiB swing over a day of up to 8 lanes) and never neared the floor. `GOH_LANE_MIN_FREE_GIB=30` stays: it holds more than a whole day's observed swing above an empty volume.
* Memory never read low (`low: null` on all 44). Re-run this join in the weekly review; a ceiling whose refusals do not shorten the waiting is the next change.

The same hook keeps a SUBAGENT to its loop queue item (LOOP.FOREIGNEDIT, `lib/queue_hold.py`): an in-progress item of `~/Projects/.loop/queue.json` holds the repos its `repo` field names (an `estate` item its `holds`, or every repo), `loopctl start ID AGENTID` records its agent, and a subagent's edit or changing command inside a repo whose nearest git worktree another item holds is denied naming the holder; its own items' repos, an unheld repo, a linked worktree inside a held checkout, `git fetch` and `git worktree` pass. | `env.CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` | `12000` | Claude Code's own Read cap (tools-reference.md#large-files; default 25,000): a whole file over it comes back as its first page with a `PARTIAL view` notice naming the next `offset`/`limit`, and a ranged read over it is refused with an error naming `offset`/`limit` or Grep. (63907 tokens, cap 12000)`; `offset 1 limit 1500` (47,997 tokens) was refused; `offset 1990 limit 5` passed. So no hook.
