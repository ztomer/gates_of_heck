# Claude Code hooks (`hooks/claude/`, wired in `~/.claude/settings.json`)
Order: 190
Level: 2

Read from the hook's environment (the settings file's `env`, or the shell Claude Code started in), never from `.gatesrc`.

`discard_guard.py` (PreToolUse, matcher `Bash|Monitor|Write|Edit|MultiEdit`; a command from Bash or Monitor is judged the same, `lib/shell_tools.py`) takes no key: it refuses a git command that would discard uncommitted work, and `# discard-ok: <reason>` in the command is its only escape for that; a wait loop that matches its own shell (`until ! pgrep -f "PATTERN"` with PATTERN in the command) is refused too, and `# pgrep-ok: <reason>` is the escape for that.

`agent_guard.py` (PreToolUse, matcher `Agent|Task`; and SubagentStop) takes no key of its own: its rules are `hooks/claude/model_choice.json` (`GOH_MODEL_CHOICE` names another file, for trying a change before committing it). A non-exempt spawn must name `model` AND `effort` and declare them in its prompt as `Model-choice: <model>@<effort> because <tags>`, which the file's `tiers` must accept (the deny prints the table); an allowed spawn gets the report contract (`Status:` first) appended once, and it and its outcome (tokens, status, report) are rows of goh.db's `agent_spawns` (`lib/hook_ledgers.py`, GOH.STATEDBS4: the write waits at most 5 s for goh.db, then the row is spilled beside it and counted, and the spawn goes on). The rules in force are a PROFILE (`profiles`, GOH.ULTRARULES, owner 2026-11-15): `pro`, `max` (the top-level tables exactly) or `ultra`, each one's `changes` laid over `tiers`, `pool_first` and `exploration`; the active one is `profiles.declared` (set by a person; today `ultra`), dropped ONE step along `profiles.order` by the budget guard when token-pool's Claude 7-day meter (`$POOL_STATE_DIR/meter.json`, default `~/.cache/token-pool`) reads under `budget_guard.min_left_pct`, is older than `max_age_h`, or cannot be read; every refusal names the profile and why it is active, and the spawn line keeps `profile`, `profile_why` and `meter` (the outcome line keeps `load` and `cores`). A spawn on a tier the active profile's `pool_first` names (max and pro: every tier but `never`, opus included, owner ruling 2026-11-01; ultra: `lookup` only) must also say, in a `Pool: tried <what mcp__pool__ask returned>` or `Pool: unfit because <reason>` line, that token-pool's free pools were tried first or cannot do the work; the ledger keeps the line as `pool`. `lean_types` (GOH.LEANAGENT) refuses a write spawn of a heavy type (`general-purpose`, `claude`: ~70.6k tokens of MCP tool names and lists every turn) with the lean type goh installs, `repo-worker` or `repo-worker-ui` (on-screen QA), unless the prompt carries `Agent-type: <type> because <reason>` (ledgered as `agent_type_escape`); a read-only lookup is not steered. `exempt_agent_types` names the agent types it leaves alone; `exploration` routes cheap-tier spawns between the two cheap tiers by prompt-sha parity, and (`opus_to_cheap.enabled`, off: the owner's switch) a fraction of checkable opus spawns down. `python3 scripts/agent_audit.py [--json] [--offline] [--root DIR] [--min-n N]` reads the ledger (`GOH_GH` names the gh command); `python3 scripts/model_choice_watch.py [--install] [--notify osascript|CMD|'']` is the weekly re-check and usage review (`scripts/usage_review.py`: the week's spawns, pool lines, redo, escalation and spend per class, the meter's minimum and the load when agents landed propose a profile and the values it changes, by `profiles.review`; a macOS notice when it proposes anything; it never edits the rules file). Register the entries in `hooks/claude/registrations.json`, and install the agent types in `hooks/claude/agents/` into `~/.claude/agents/`, with `python3 scripts/apply_claude_hooks.py` (never hand-widen a matcher in settings.json: a matcher belongs to its whole group, so widening one that also holds a foreign hook such as `rtk hook claude` widens that hook too) as written: a python hook ends `|| exit 1`, so a missing script is a visible hook error, never a block on every call.

`lane_room.py` (called by `agent_guard.py` on every WRITE spawn -- any judged spawn whose tier is not a `lean_types` read-only tier; Explore and the other exempt types are never asked; GOH.ADAPTLANES) takes `lib/capacity.py`'s reading, the one `goh capacity [--json]` prints (exit 0 room, 1 none), and its rule: room while at most `GOH_LANE_MAX_WAITING` long-lane gates wait for a slot, the measured CPU idle is at or over `GOH_LANE_MIN_IDLE_PCT` (the 5-minute load per core judges only when the idle cannot be measured: macOS's load average counts I/O-blocked threads, LOOP.FILLIDLE), free disk is over a floor, and memory is not low by `lib/mem_admit.py`'s own keys (`GOH_MEM_MIN_PCT`, `GOH_SWAP_MAX_PCT`). The reading is the gate slots' own state (their flock'd files and `waiting/` tickets) plus the load, memory, disk and the CPU weight of the gates in flight (each holder's median cpu-s per wall-s in the one timing record, `capacity.gate_weight`, the weight GOH.CPUADMIT replayed and D-0009 left informational: admission stays a count; a holder is named by its record's repository key among the registered repos, so a lane worktree's gate weighs as its repo). A reading with any part unread ADMITS with a warning, in every mode. A spawn whose prompt has a line opening `Owner-asked: <the owner's words>` is DEFERRED with no room in `refuse` mode (line `owner-deferred`: the owner asking for the work is not the owner asking for it to run at once, GOH.OWNERASKCAP, mistakes.json M5), admitted in `warn` (`owner`), and refused in every mode above the hard ceiling -- load1 over 4x the cores, or CPU idle under 5% (`owner-refused`, naming the numbers) -- its line carrying the words (the marker must open its own line; a brief that quotes it is a plain spawn). A refusal is a DEFERRAL: it names what the reading lacked and tells the coordinator to re-dispatch the spawn unchanged once `goh capacity` exits 0; the coordinator's own caps (8 agents, 8 goh lanes, set by its loopctl) stay the hard ceiling above this rule. Every judged spawn is one row of goh.db's `lane_starts` (`lib/hook_ledgers.py`, GOH.STATEDBS4; was `lane-starts.jsonl`): verdict (`room`, `warned`, `refused`, `owner`, `unread`), reasons, mode, the queue item the prompt names (`Queue item <ID>`: the join key below) and the whole reading, for the weekly review to tune the ceilings with. **Calibration (GOH.ADAPTLANES2, 2026-11-17/18 UTC).** The 44 lines of `lane-starts.jsonl` (all `warn`) were joined to what each admitted lane then did: spawn `tool_use_id` -> the spawn's prompt in the coordinator's transcript -> its `Queue item <ID>` (the ledger now records `item`, so the next review needs no transcript) -> the first `landq/done/<ns-enqueue>-<ID>.json` enqueued after the spawn (`started`, `finished`, `slot_wait_s`, its log's `pre-land green in N s: waited W s, ran R s`) and the timing ledger's `land`/`push` rows (`wall_s`, `cpu_s`, `load1`, `load_end`). 24 distinct lanes joined (the rest landed elsewhere or were still running). A lane's WAITING is landq queue (`started` minus enqueue) + slot wait + pre-step wait.

* Load per core AT SPAWN does not predict the lane's own waiting: correlation 0.06; median wait 278 s under 1.5 per core (n=4), 937-1150 s at 1.5-2.5 (n=6), 19 s at 2.5-3.5 (n=3), 319 s at 3.5-5 (n=9). Spawn to enqueue is 5-80 min (median 29), so the load at spawn is long gone by the land. `goh land --report` for 2026-11-17: 843 min enqueue-to-start waiting against 1170 gate minutes, of which only 58 were slot waits: the waiting that lanes add is the land queue's.
* The load ceiling is therefore set where extra load stops buying work for the gates already running (101 green push/land rows over 60 s, binned by mean load per core over the run): a gate's cpu-s per wall-s is 2.55 / 2.82 / 2.77 at <1.5 / 1.5-2 / 2-2.5 per core, then 2.04 / 2.23 / 1.59 at 2.5-3 / 3-4 / 4-5; the median goh land wall is 650 / 641 s at 1.5-2.5, then 677 / 805 / 730 / 948 s at 2.5-3 / 3-4 / 4-5 / 5-7. Past 2.5 per core a new lane's work only stretches the gates in flight: `GOH_LANE_LOAD_PER_CORE=2.5` (was 2.0 by judgment). At 2.5, 23 of the 44 spawns would have been refused (31 at 2.0).
* Waiting tickets at spawn: 7 of 44 spawns saw a long-lane waiter; the 3 joined lanes among them waited a median 0 s (21 lanes that saw none: 418 s). The longest slot wait any joined land saw was 404 s, shorter than the shortest spawn-to-enqueue gap (5 min): one waiter clears before the new lane's first gate asks. Two waiters are a full queued round of both slots: `GOH_LANE_MAX_WAITING=1` (was 0).
* Disk: free space on `~/.cache` ranged 96.3-118.9 GiB across the 44 readings (a 22.6 GiB swing over a day of up to 8 lanes) and never neared the floor. `GOH_LANE_MIN_FREE_GIB=30` stays: it holds more than a whole day's observed swing above an empty volume.
* Memory never read low (`low: null` on all 44). Re-run this join in the weekly review; a ceiling whose refusals do not shorten the waiting is the next change.

`agent_stalls.py` (UserPromptSubmit, GOH.STALLAGENT; also `goh agent-stalls [--minutes N] [--max-age-hours H] [--subagents DIR]... [--projects DIR] [--now EPOCH] [--json]`) names each subagent of the coordinator's session that is not done (a `finished` agent that stopped with a background job pending and no `Status:` report is not done) and whose transcript has been still for `GOH_AGENT_STALL_MINUTES` minutes (default 20; one older than `--max-age-hours`, default 24, is a dead session's residue): its last words and each un-notified background job, alive with its pids or gone. On a prompt it adds the list to the coordinator's context and shows it to the owner; it never blocks. `--now`, `--subagents` and `--projects` are its seams (the clock, the transcripts); the command exits 1 when any agent is stalled. `--notify [--state FILE] [--log-path FILE]` (GOH.STALLNOTIFY) is the owner's channel when the coordinator is idle and nothing will wake it: it posts one macOS notification (`osascript`, text as argv) per stall whose every pending job is gone, once per stall, and exits 0; nothing schedules it any more (the launchd job `com.ztomer.goh-agent-stalls` is retired into `.loop`'s `com.ztomer.loopctl-tick`). State: `~/.cache/goh/agent-stalls-notified.json`; log: `~/Library/Logs/goh-agent-stalls.log`, moved to `.1` past 256 KiB.

`appstate.py` (called by `agent_guard.py`, GOH.APPSTATE) watches the owner's login-item apps across an agent: at each spawn it records which login-item apps are running (System Events' `path of every login item`, matched against `ps -axww -o comm=` executables under `<app>/Contents/MacOS/`), and at the agent's SubagentStop it names each one running before and not after on the outcome line (`apps`) and in a `systemMessage`. It never relaunches one (GOH.APPRESTOREOWNER): the guard cannot tell an agent's quit from the owner's, and a closed app stays closed; a lane that needs an app starts it and quits what it started. Unreadable state reports nothing. Its two reading keys are TEST SEAMS, never set in a real session: `GOH_APPSTATE_ITEMS_CMD` (prints the login-item app paths, one per line) and `GOH_APPSTATE_RUNNING_CMD` (prints running executables' paths, one per line), each split like shell words and run without a shell. Under goh's suite the module runs no default: without both it reads nothing. `python3 hooks/claude/appstate.py running` prints what it sees. Pinned by `test_claude_appstate.py`. An app the owner removed while the agent ran (no longer a login item, or `GOH_APPSTATE_INSTALLED_CMD` -- a test seam, default `test -d` -- says it is not installed) is not reported (GOH.APPCLOSE); each reading records when every login-item app was last seen running (`appstate/seen.json`, shared by all agents), so the message names the agent and the window: last seen running at T1, gone by T2. `app_quit.py` (a rule of `discard_guard.py`) refuses an `osascript` quit of a login-item app by name or bundle id; escape `# quit-ok: <reason>`.

`hold_guard.py` (PreToolUse, matcher `Bash|Monitor|Write|Edit|MultiEdit|NotebookEdit`) takes no key: a repo whose local git config carries `goh.hold` (or the first archive's `goh.archived`) is ON HOLD (`lib/repo_hold.py`), and an edit inside it, or a Bash command that would change it (a writing git verb run in it, a file verb or redirection naming a path in it, chmod/chown/chflags on it or recursively on an ancestor, `release_hold.sh` on it), is denied naming the hold's reason and its lift command. The git gates refuse commit, merge (commit-msg), `git am` (pre-applypatch) and push in a held repo the same way. `scripts/hold_repo.sh <repo> --reason <why> [--lift <cmd>] [--read-only]` holds (read-only also runs `chmod -R a-w` and records `goh.holdReadOnly`), `scripts/release_hold.sh <repo>` lifts (the owner's, from their own terminal). `scripts/archive_repo.sh <repo> [--reason <why>]` archives the owner's GitHub repo and holds the clone read-only; `scripts/unarchive_repo.sh <repo>` lifts it once GitHub says it is live. Their seams: `GOH_GH` (the gh command), `GOH_GH_USER` (the owner's login, default `gh api user`), `GOH_HOLD_INTERACTIVE=1` (answer the unarchive offer without a terminal); `GOH_HOLD_LIFTED_BY` is internal (the wrapper that owns a hold's lift, set by unarchive_repo.sh for release_hold.sh).

`spawn_register.py` (PostToolUse, matcher `Agent|Task`, GOH.SPAWNREGISTER) takes no key: when a spawn returns, the first `Item <ID>` / `item <ID>` in the brief that names an in-progress item of the loop queue whose agent still reads `pending-spawn` is registered to the spawned agent (the response's `agentId`, structured or in its text) by running `.loop`'s own `loopctl --queue Q start ID AGENT` (an estate item keeps `--repos` its holds, else `--estate`) from the queue's directory, so a lane's first write is not refused for an unrecorded agent. Its seam is `GOH_LOOP_QUEUE`; a refusing loopctl is a visible, non-blocking hook error. A write that still races it is refused by `hold_guard.py` with `registration pending: retry in a few seconds`.

The same hook keeps a SUBAGENT to its loop queue item (LOOP.FOREIGNEDIT, `lib/queue_hold.py`): an in-progress item of `~/Projects/.loop/queue.json` holds the repos its `repo` field names (an `estate` item its `holds`, or every repo), `loopctl start ID AGENTID` records its agent, and a subagent's edit or changing command inside a repo whose nearest git worktree another item holds is denied naming the holder; its own items' repos, an unheld repo, a linked worktree inside a held checkout, `git fetch` and `git worktree` pass. The tie is the hook event's `agent_id`, which Claude Code sets only inside a subagent, so the main thread (the coordinator) is never refused. A subagent's `gh run watch|view|list`, `gh api .../actions` or `gh pr checks --watch` is denied there too, naming `loopctl ci <sha> --repo OWNER/NAME --wait` (LOOP.GHDOOR, `hooks/claude/ci_door.py`). Its seam: `GOH_LOOP_QUEUE` (the queue file; repo names resolve under its grandparent). A missing or unparseable queue holds nothing. Every goh read of the loop queue goes through `lib/queue_read.py` (LOOP.QUEUEARCHIVE): the SQLite store `loop.db` beside the named file when it exists, opened read-only, else the JSON file; its docstring is the store's documented layout, and `tests/test_queue_read.py` refuses any other parse of the queue in goh.

The same hold is judged at COMMIT, whoever runs git (GOH.HOLDSUBPROC, `lib/commit_hold.py`): `GOH_LOOP_AGENT` is not a setting but the stamp the Bash guard (`discard_guard.py`) puts at the head of every subagent's command (`export GOH_LOOP_AGENT=<agent id>`), inherited by every process the shell starts; `gates/hook.sh`'s pre-commit refuses a commit whose `GOH_LOOP_AGENT` is not the agent of the in-progress item holding the repo. Unset (the main thread, the owner, a non-Claude shell) judges nothing.
