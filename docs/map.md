* `.github/actions/goh-floors` (`action.yml` + `floors.sh` + `shellcheck.sha256`) — the ONE way a
  CI runner meets goh's tool floors (G7): reads python3's and shellcheck's floors from
  `gates/required_tools.tsv`, installs the Python floor (setup-python) and a shellcheck at or above its
  floor (the runner's, else a checksum-verified release), then asks goh's own judges

  on `--full`: `-n 12 --dist loadgroup`, serial fallback without xdist).
* `tools/load.py [N -- CMD...]` — the ONE way to make load on this machine, and it reaps itself.
  It takes the registry slot (`GOH_LOAD_DIR`, default `~/.cache/goh/load`), refusing a second
  experiment while one holds it; starts N spinners, REGISTERING each one (pid + start time)
  BEFORE it is allowed to burn (a spinner waits on a release pipe, and exits if the pipe closes
  first, so one that was never released never spins); runs the command under the load; kills
  exactly the spinners it registered on the way out (EXIT/TERM/INT/HUP), VERIFIES that none
  survived, and drops the registry. It also watches for its OWN owner dying and cleans up then.
  It is BOUNDED by its own clock (G1c): a deadline is always in force (30 min unless `--max 90m`
  / `--max 2h` names another), and on expiry the command's whole tree (its process group, and
  every descendant, one that left the group too) and every spinner are killed and it exits 124
  naming the deadline; a signal or a dead owner kills the command's tree as well. N above the
  core count is refused unless `--oversubscribe` is passed (`GOH_LOAD_NCPU` is the test seam).
  A command run at BACKGROUND priority (G1f: `taskpolicy -b`, a QoS clamp, `nice`/`renice` >= 10,
  `chrt --idle`, after env/sudo-style prefixes and inside `sh -c`) is refused before any spinner
  starts: N spinners starve it by construction (`lib/load_priority.py`); `--background-ok
  <reason>` is the escape. `--status` says who holds the slot; `--reap` clears a slot whose owner is gone. Pinned by
  `test_load_tool.py`.
